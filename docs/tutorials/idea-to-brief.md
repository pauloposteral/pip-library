# Turn an idea into an observable brief

Choose one person and one problem. Write the smallest useful outcome. Replace “easy to use” with an observable criterion: an empty title is rejected and the list is unchanged. List exclusions, such as accounts and collaboration. Use the product brief and QA matrix; mark proposed tests NOT_TESTED. Review the plan with the person affected before coding.
